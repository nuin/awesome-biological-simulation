# Bygul

> Simulate tiled-amplicon sequencing reads from two sample genomes mixed at chosen proportions, given a reference and a primer BED scheme.

Licence: BSD-2-Clause · [Source code](https://github.com/andersen-lab/Bygul)

## What it simulates

Bygul simulates tiled-amplicon sequencing, the method used for SARS-CoV-2 genome surveillance. It takes two or more sample genomes, a reference and a primer BED file. It finds each primer pair in each genome, cuts the amplicon between them, and simulates paired-end reads with [wgsim](wgsim.md) (or mason or ART). It mixes samples at proportions you set. It returns one pair of FASTQ files with all reads, plus per-sample amplicons, reads and a stats table.

Key assumptions: an amplicon exists only if both primers match the genome within `--maxmismatch` mismatches. Every amplicon gets the same read budget (`--readcnt`).

## When to use it

- Test a lineage-deconvolution or mixed-infection tool on known mixtures.
- Study amplicon dropout: which primers fail on a variant genome.
- Check a primer scheme against a new variant.

Alternatives on biosimhub: `wgsim` and [DWGSIM](dwgsim.md) simulate whole-genome short reads without primers. [InSilicoSeq](insilicoseq.md) simulates Illumina metagenomes.

## Install it yourself

Bygul 4.0.5 is on bioconda (dry-run resolved, build `pyhdfd78af_0`, 25 kB).

```
conda create -n bygul -c conda-forge -c bioconda bygul=4.0.5
conda activate bygul
```

Minimal command:

```
bygul simulate-proportions --genomes s1.fa,s2.fa --reference ref.fa --primers primers.bed --proportions 0.8,0.2 --outdir results
```

Defaults from `--help`: 500 reads per amplicon, read length 150, insert size 200 (SD 10), one mismatch allowed, wgsim error rate 0.0001, 4 threads, simulator `wgsim`. The BED name column must look like `scheme_3_LEFT`.

## Run the tested example

This recipe builds Bygul in a container and runs the example below. It needs [Docker](https://docs.docker.com/get-docker/) and nothing else. It last ran on 2026-10-12 in 1.1 s.

1. Download [bygul-recipe.tar.gz](https://biosimhub.pages.dev/guides/bygul/bygul-recipe.tar.gz) (Dockerfile, example sample1.fa, sample2.fa, reference.fa, primers.bed, run.sh).
2. Unpack it and run the script:

   ```sh
   tar -xzf bygul-recipe.tar.gz
   cd bygul
   sh run.sh
   ```

![Terminal recording of the Bygul example run](https://biosimhub.pages.dev/media/bygul/run.gif)

<details><summary>What run.sh does</summary>

```sh
docker build -t biosimhub/bygul:4.0.5 .
mkdir -p out && chmod a+w out
docker run --rm \
  --user "$(id -u):$(id -g)" -e HOME=/tmp \
  -v "$PWD/in:/work/in:ro" -v "$PWD/out:/work/out" -w /work/out \
  biosimhub/bygul:4.0.5 bygul simulate-proportions --genomes /work/in/sample1.fa,/work/in/sample2.fa \
    --reference /work/in/reference.fa --primers /work/in/primers.bed \
    --proportions 0.7,0.3 --threads 1 --readcnt 100 \
    --maxmismatch 1 --insert_size 200 --insert_size_sd 10 \
    --read_length 150 --wgsim_error_rate 0.0001 \
    --outdir . > out/bygul_log.txt
```

Inputs are read from `in/` and results land in `out/`. Change the values after each option to run your own case; the parameter table lists them.

### Parameters

| Option | Meaning | Example value | Range |
|---|---|---|---|
| `--proportions` | Read proportions (sample 1, sample 2) | 0.7,0.3 | 0.5,0.5, 0.7,0.3, 0.8,0.2, 0.9,0.1, 0.95,0.05 |
| `--readcnt` | Reads per amplicon | 100 | 1 to 5000 |
| `--maxmismatch` | Max mismatches in primer region | 1 | 0 to 5 |
| `--insert_size` | Outer distance | 200 | 50 to 1000 |
| `--insert_size_sd` | Insert size standard deviation | 10 | 0 to 200 |
| `--read_length` | Read length | 150 | 30 to 300 |
| `--wgsim_error_rate` | Base error rate | 0.0001 | 0 to 0.1 |

Ranges are the limits used for the example recipe; the program itself may accept more.


## Reading the output

The example mixes two 3,000 bp genomes at 0.7 and 0.3 using a 16-line primer BED (8 amplicons). The log lists each genome with 0 ambiguous bases.

- `reads_1.fastq` and `reads_2.fastq` (266,527 bytes each): 800 read pairs, which is 8 amplicons x 100 reads. Names look like `@2_0_195_395_0:0:0_0:0:0_0/1`, the wgsim format, with amplicon 2 first. Quality is `I` everywhere.
- `sample1/` and `sample2/`: `amplicons/amplicon_N.fasta`, `amplicons/amplicon_stats.csv`, per-amplicon read files and `reads/merged_reads_*.fastq`.
- The stats CSV has the expected primers, the sequence found, `ambiguous_bases`, amplicon start and end, and length.

Counting merged reads gives 616 pairs from sample 1 and 184 from sample 2. That is 77:23 for a 70:30 request.

The primer BED has six columns: chromosome, start, end, name, pool and strand. Scheme 1 has its left primer at `ref 30 55` in pool 1 and its right primer at `375 400`. For amplicon 1, the stats CSV records `primer_start` 30, `primer_end` 375 and `amplicon_length` 370. Its `left_match` and `right_match` equal the expected primers, so no mismatch was needed. Amplicons 2 to 8 report 400 bp.

## Your own runs

- **Skewed mix.** `--proportions 0.95,0.05`. Result: 776 pairs from sample 1 and 24 from sample 2 (97:3).
- **Strict primers and more depth.** `--proportions 0.5,0.5 --readcnt 500 --maxmismatch 0`. Result: 3,538 pairs. Sample 1 has 6 amplicons with 231 pairs each (1,386), because amplicons 3 and 4 are gone. Sample 2 keeps 8 amplicons with 269 pairs each (2,152). The 50:50 request came out as 46:54 per amplicon.
- **Your scheme.** Use the reference your BED coordinates refer to. Check `amplicon_stats.csv` for rows where `left_match` or `right_match` differ from the primer.

## Pitfalls

- **Strict mismatch silently drops amplicons.** With `--maxmismatch 0` two sample 1 amplicons vanished. Compare amplicon counts across samples before you read dropout as biology.
- **Realized proportions drift.** Observed splits were 77:23, 97:3 and 46:54 for 70:30, 95:5 and 50:50. Count reads per sample if the exact mix matters.
- **Reference must match the BED.** The BED coordinates refer to `--reference`. Sample genomes are searched for the primer sequences.
- **Option spelling.** The README spells some options differently from the tool's help. Use `--maxmismatch` and `--insert_size`.
- **Default threads is 4.** Pass `--threads 1` on a small machine.
