# LightDock

> Rigid-body protein-protein docking with a glowworm swarm optimiser; returns a ranked list of poses and the top complexes as PDB files.

Licence: GPL-3.0 · [Source code](https://github.com/lightdock/lightdock)

## What it simulates

LightDock predicts how two biomolecules fit together: protein with protein, protein with peptide, or protein with DNA. It treats both partners as rigid bodies and searches for the ligand pose that scores best on the receptor surface. The search uses Glowworm Swarm Optimization (GSO).

The receptor stays fixed. LightDock places points over its surface, and each point is a swarm centre. Each swarm holds a set of glowworms, and each glowworm is one candidate ligand pose. Glowworms move toward poses with a better score (more "luciferin") in translation and rotation. Swarms are independent, so the work spreads across as many CPU cores as there are swarms. Optional extras are backbone flexibility with an anisotropic network model (ANM) and residue restraints from experiments.

The key assumptions are rigid partners, a coarse scoring function, and a result that is a ranked list of poses, not a free energy. Scoring functions in the 0.9.4 source tree are fastdfire, dfire, dfire2, cpydock, pisa, sipper, tobi variants, mj3h, dna, ddna, vdw and sd. Without a choice, the program uses its default.

## When to use it

- You have two structures and no information about the interface, and want candidate complexes from a CPU-only tool.
- You have residue restraints (for example mutation or NMR data) and want them to bias the starting poses.
- You want to plug in your own scoring function: the optimiser does not depend on the force field.

Alternatives:

- [AutoDock Vina](vina.md) docks a small molecule into a protein, not two proteins.
- [HADDOCK3](haddock3.md) is information-driven docking with flexible refinement. It needs the CNS licence.
- [OpenMM](openmm.md) can test whether a docked pose stays stable in a short molecular dynamics run.

## Install

LightDock 0.9.4 (August 2023) is on PyPI under GPLv3. It has no conda package. Its README gives one command:

```
pip install lightdock
```

The package compiles Cython extensions, so a C compiler is needed. Its dependencies are NumPy, SciPy, Cython, ProDy and freesasa. MPI support through mpi4py is optional. The README lists Linux and macOS as supported systems and Windows as unsupported.

It builds a Python 3.11 image, pins `numpy<2` and `cython<3` for the build, and installs `lightdock==0.9.4`. It targets linux/arm64.

## Run the tested example

This recipe builds LightDock in a container and runs the example below. It needs [Docker](https://docs.docker.com/get-docker/) and nothing else. It last ran on 2026-10-17 in 3.6 s.

1. Download [lightdock-recipe.tar.gz](https://biosimhub.pages.dev/guides/lightdock/lightdock-recipe.tar.gz) (Dockerfile, run_lightdock.py, example receptor.pdb, ligand.pdb, run.sh).
2. Unpack it and run the script:

   ```sh
   tar -xzf lightdock-recipe.tar.gz
   cd lightdock
   sh run.sh
   ```

![Terminal recording of the LightDock example run](https://biosimhub.pages.dev/media/lightdock/run.gif)

<details><summary>What run.sh does</summary>

```sh
docker build -t biosimhub/lightdock:0.9.4 .
mkdir -p out && chmod a+w out
docker run --rm \
  --user "$(id -u):$(id -g)" -e HOME=/tmp \
  -v "$PWD/in:/work/in:ro" -v "$PWD/out:/work/out" -w /work/out \
  biosimhub/lightdock:0.9.4 python /opt/driver/run_lightdock.py /work/in/receptor.pdb /work/in/ligand.pdb \
    --swarms 10 --glowworms 10 --steps 10 --scoring fastdfire \
    --seed 324324 --seed-points 324324 --top 5 > out/lightdock_log.txt
```

Inputs are read from `in/` and results land in `out/`. Change the values after each option to run your own case; the parameter table lists them.

### Parameters

| Option | Meaning | Example value | Range |
|---|---|---|---|
| `--swarms` | Swarms (regions of the receptor surface) | 10 | 1 to 60 |
| `--glowworms` | Glowworms per swarm | 10 | 5 to 200 |
| `--steps` | Optimisation steps | 10 | 1 to 100 |
| `--scoring` | Scoring function | fastdfire | fastdfire, dfire, dfire2, cpydock |
| `--seed` | Optimiser seed | 324324 | 1 to 2147483647 |
| `--seed-points` | Starting-positions seed | 324324 | 1 to 2147483647 |
| `--top` | Top structures to write | 5 | 1 to 20 |

Ranges are the limits used for the example recipe; the program itself may accept more.


## A first run

The commands below follow the LightDock basics tutorial (https://lightdock.org/tutorials/basics) and the 0.9.4 command-line parser. The example inputs are two test structures from the LightDock repository, a 96-residue receptor and an 89-residue ligand (barstar), used under GPL-3.0.

```
lightdock3_setup.py receptor.pdb ligand.pdb -s 10 -g 10 --noxt --noh
lightdock3.py setup.json 10 -c 1 -s fastdfire
lgd_rank.py 10 10 --ignore_clusters
lgd_top.py receptor.pdb ligand.pdb rank_by_scoring.list 5
```

- `lightdock3_setup.py` writes `setup.json`, an `init` folder, one `swarm_N` folder per swarm and parsed copies of both structures. `-s` is the number of swarms and `-g` the glowworms per swarm. The tutorial says the original paper used 400 swarms and 300 glowworms and that smaller molecules can use fewer.
- `lightdock3.py` takes the setup file and the number of steps, and writes `gso_<steps>.out` in each swarm folder. `-c` sets the CPU cores and `-sg` the optimiser seed.
- `lgd_rank.py` takes the number of swarms and steps and writes `rank_by_scoring.list`.
- `lgd_top.py` writes the best structures as PDB files.

The recipe's helper script `run_lightdock.py` chains these four steps with 10 swarms, 10 glowworms per swarm and 10 steps. These are small values chosen for a short run.

## Reading the output

- `rank_by_scoring.list` is a text table, one row per solution, sorted by score. Columns identify the swarm and glowworm, and give the score and clash information. Higher scores are better poses.
- `top_1.pdb` and the other top files are the complexes, with the ligand moved to its docked position.
- `setup.json` records the setup settings.

A pose with a better score is not a confirmed binding mode. The tutorial's clustering step (`lgd_cluster_bsas.py`) groups poses; consistent poses across swarms are stronger evidence than one high score.

The recipe has been run on biosimhub; its recorded output files are listed with the recipe below.

## Pitfalls

- **Too few swarms miss the interface.** The default of 400 swarms and 300 glowworms in the paper is for full-size proteins. The recipe's 10 and 10 only show the workflow.
- **Hydrogens and OXT atoms.** The tutorial advises `--noxt` for several scoring functions and `--noh` for DFIRE, FASTDFIRE and DFIRE2.
- **Inputs are copied.** LightDock writes parsed copies and index files beside the inputs, so run it in a writable folder.
- **Rigid bodies only by default.** Use `--anm` at setup to add backbone flexibility.
- **Python and NumPy versions.** The 0.9.4 release predates NumPy 2, so the recipe pins `numpy<2`.
